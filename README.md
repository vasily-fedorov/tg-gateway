# gateway-relay — межагентный обмен через Telegram-супергруппу

Плагин Hermes для агентов, живущих в форум-супергруппе Telegram. Даёт
**подтверждаемый человеком** канал «агент → агент»: карточки с кнопками в
отдельном топике, парковка входящих, hop-бюджет от петель, аудит.

Рассчитан на мультиплексированный гейтвей Hermes: у каждого агента есть
изолированный профиль `gateway` (тулсеты: `clarify` + этот плагин), который
принимает сообщения из служебного топика через `gateway.profile_routes`.

## Что делает

| | |
|---|---|
| **Отправка** | `relay_send(target, text)` ничего не отправляет: проверяет allowlist/фильтры/лимиты, паркует запрос и рисует карточку в топике подтверждений с кнопками «Отправить»/«Отклонить». Отправка — по клику владельца (callback-хендлер плагина). |
| **Приём** | Сообщение другого бота в служебном топике не доходит до модели: хук паркует его и рисует карточку «Принять?». После «Принять» watcher делает тихий ход профиля (`hermes -p <profile> chat -q`) и публикует ответ реплаем с упоминанием отправителя. |
| **Вопрос своему профилю** | `ask_default(question)` — тихий ход `hermes -p <profile> chat -q`, аргументы списком, без `shell=True`. |
| **Инбокс** | `gateway_inbox(ack=false)` — принятые владельцем сообщения и ответы на них. |

## Безопасность (не зависит от поведения модели)

1. **Адресаты структурны** — только ключи из `gateway-routes.json`; выдумать
   `chat_id`/`thread_id` нельзя.
2. **Кнопка = подтверждение.** Ни модель, ни субагент не могут подтвердить
   отправку: колбэк проверяет, что нажал владелец (`owner_ids`), и только тогда
   отправляет. Кодов `APPROVE` нет и не будет.
3. **Изоляция входящего** — бот принимается только из этого чата, только из
   реестра, только с явным `@нашего_бота`. Текст не попадает в модель до
   клика владельца.
4. **Фильтры утечек и инъекций** на исходящем тексте (токены, ключи, пароли,
   длинные base64/hex; попытки подмены инструкций).
5. **Анти-петля** — `[gw-hop:N]` в каждом исходящем; входящее с `hop > 3` не
   паркуется. Тихий ход обязан ответить `SKIP`, если в сообщении нет вопроса или
   просьбы; мета-ответы («карточка не доставлена» и т.п.) не публикуются.
6. **Аудит** — `logs/gateway-relay-audit.jsonl`: `card_sent`, `card_rejected`,
   `card_unauthorized`, `bot_inbound_parked`, `inbound_approved`,
   `inbound_answered`, `inbound_skipped`, `hop_limit`, `rate_limited`,
   `refused`. Пишутся hash и длина, не текст.

MCP-серверы плагину не нужны; shell/файловых/сетевых инструментов он не даёт.

## Установка

```bash
hermes plugins install <owner>/<repo> --enable      # из git
# или локально: скопировать каталог в ~/.hermes/plugins/gateway-relay
```

Плагин ставится в **два** дома:

- `<profile-home>/plugins/gateway-relay` — профиль `gateway`: здесь регистрируются
  инструменты и watcher;
- `<launch-home>/plugins/gateway-relay` — профиль запуска (default): здесь
  регистрируется только хук и фабрика callback-хендлера кнопок. Без этой копии
  кнопки не работают: PTB-хендлеры берутся из менеджера плагинов **профиля
  запуска**.

В конфиге профиля `gateway` включите инъекции — не для инъекций (они не
используются), а чтобы плагин мог ставить задачи в свой профиль, если вы
добавите свои обработчики:

```yaml
plugins:
  enabled:
    - gateway-relay
  entries:
    gateway-relay:
      allow_gateway_injection: true
```

## Конфигурация профиля `gateway`

```yaml
platforms:
  telegram:
    allow_bots: mentions          # принимать сообщения ботов
    bots_require_mention: true    # ...только с явным @нашего_бота
    group_allowed_chats: ['-100…']  # только эта супергруппа
    allowed_chats: ['-100…']
    group_policy: mention_only
    ignored_threads: [1]
platform_toolsets:
  telegram: [clarify, gateway_relay]
delegation:
  model: <ваша модель>
```

## Реестр `gateway-routes.json`

Живёт в домашнем каталоге профиля `gateway` (runtime-файл, не в git):

```json
{
  "chat_id": -1004418865255,
  "approvals_thread": 1,
  "owner_ids": [123456789],
  "limits": {"max_text": 3000, "per_hour": 20},
  "self": {"bot_username": "my_gateway_bot", "bot_id": 1111111111},
  "bots": {
    "peer_alias": {
      "title": "peer (топик 2)",
      "bot_username": "peer_bot",
      "bot_id": 2222222222,
      "chat_id": -1004418865255,
      "thread_id": 2,
      "transport": "telegram",
      "enabled": true
    }
  }
}
```

- `approvals_thread` — топик, куда уходят карточки (например, General = 1).
- `self` — свой бот: нужен для mention-гейта (Telegram срезает наш `@handle` из
  текста у адресата, поэтому проверка идёт по `raw_message`).

Управление реестром из чата (перехватывает хук, только владелец):

```
ROUTE <имя> <thread_id> [заголовок]
ROUTE DEL <имя>
ROUTES
```

## Ограничения Hermes, которые плагин обходит осознанно

- `require_mention` резолвится из профиля **запуска**, а не маршрутизированного →
  mention-гейт реализован в хуке.
- `PluginContext.inject_message` не может разбудить чат чужого профиля →
  принятое сообщение обрабатывается тихим ходом профиля, а не инъекцией.
- `send_clarify` всегда пишет в топик сессии → карточки рисует плагин, а не
  `clarify`.
